# iOS 书源阅读器设计规格

## 目标与产品定位

构建一款独立的 iOS 阅读应用，以 Legado 风格的用户自配置书源为主要内容入口。应用由 iOS 客户端直接访问书源站点，不运行或依赖本项目自建服务端。首要产品目标是：用户配置的多个有效书源能方便地参与搜索，搜索结果尽可能完整，同时单个来源故障不拖垮整次搜索。

新应用位于独立仓库 `BookReaderIOS`。`参考软件源码/Legado-master` 与 `参考软件源码/Yuedu-reader-main` 仅作只读参考；不在其中修改文件，也不直接复制未确认许可证允许复用的代码或品牌资源。Legado 源码目录中未发现许可证文件，因此仅借鉴其功能、行为与架构思路。Yuedu 声明采用 MPL-2.0，任何未来代码复用仍须单独检查许可证与依赖义务。

## 用户与核心流程

用户通过粘贴、选择本地文件或输入 HTTP(S) 订阅地址导入 Legado 格式书源，启用所需来源后搜索书名。应用并发请求多个来源，逐步显示已完成来源的结果；用户查看书籍详情与目录，选择章节开始阅读。用户可将书加入本地书架、恢复上次阅读位置、按需缓存章节，并在来源失效时切换可用来源。

## 功能范围

### 书源管理与运行时

- 导入单个或多个 Legado 书源 JSON；支持剪贴板文本、本地文件和用户提供的 HTTP(S) JSON/订阅 URL。
- 本地管理书源：查看、编辑、启用/停用、删除、按名称/分组整理；提供单源测试和规则调试反馈。
- 面向尽可能高的书源命中率，规则运行时以 Legado 常见语义为兼容目标：HTTP 请求与模板变量、请求头和 Cookie、CSS、XPath、JSONPath、正则及 JavaScript 规则。
- 对依赖登录或 Cookie 的来源提供用户可控的会话配置；验证码、站点反自动化与特殊 Web 登录不承诺通用支持，须明确报告失败原因。
- JavaScript 规则必须在受限运行时执行，仅提供书源所需的桥接能力；不允许规则任意访问本地文件、钥匙串或应用内部数据。网络访问遵循当前规则引擎允许的请求能力，并应能取消、限时和隔离执行。

### 搜索与发现

- 搜索已启用且含搜索规则的来源；允许用户临时选择来源范围。
- 对来源请求进行有界并发和逐源超时；支持取消；某来源失败不取消其他来源。
- 结果逐步展示，标明来源、来源状态与错误；同名/同作者结果可以聚合，但必须保留每个匹配来源及其书籍地址，支持从聚合项查看或切换来源。
- 搜索结果排序应稳定且不抑制小来源的命中；提供关键词历史的本地清理能力（不作为阅读统计）。
- 书籍详情展示书名、作者、简介、封面、来源等已有元数据；目录支持加载状态、错误重试、缓存恢复及刷新。

### 书架、阅读与缓存

- 提供本地书架、基础分组、排序、移除和来源切换；保存最近章节/阅读位置，仅用于恢复阅读，不生成阅读统计面板。
- 提供在线章节阅读、目录跳转、上一章/下一章和基础阅读外观设置（字体、字号、主题、行距、边距及翻页/滚动方式）。
- 缓存目录和用户请求的章节；支持当前章节邻近预取、缓存状态展示、清理与缓存章节离线打开。缓存应有清晰的本地存储边界与删除行为。
- 内容净化/替换规则可作为后续扩展，不阻塞首个可用版本的书源搜索和阅读主路径。

## 明确不在范围内

- 本项目自建服务端、账户体系、云端内容代理或服务端搜索。
- Yuedu 的 EPUB、TXT、CBZ 等本地文件书库/格式阅读和相关导入流程。
- 标注、高亮、笔记、书签、阅读统计、iCloud 同步及广告。
- RSS、WebDAV、OPDS、本地 Web 管理服务、桌面小组件、社交功能和付费订阅。
- 对第三方网站可用性、书源规则永久有效、验证码绕过或所有网站登录流程作保证。

## 架构建议

- **iOS UI：**SwiftUI，按书源管理、搜索/发现、书架、书籍详情、目录和阅读器拆分界面与状态模型。
- **领域层：**Source、Search、Book、TOC、Chapter、Shelf、ReadingPosition 等清晰模型；使用用例编排 UI，不让视图直接拼接网络和解析逻辑。
- **书源运行时：**解析书源 JSON、请求描述、规则语法与结果映射；规则执行有版本化兼容边界和 fixture 测试。
- **网络层：**URLSession 负责普通 HTTP；Cookie/请求头按来源隔离；超时、并发上限、取消、响应解码和错误分类集中处理。若特定规则确需浏览器执行能力，再以隔离适配器评估，不作为默认请求路径。
- **本地存储：**SwiftData 或等价本地持久化存书源、书架元数据、阅读位置和设置；章节正文缓存单独管理，便于限额和清理。所有数据仅留在设备本地。
- **阅读排版：**以原生文本排版为先，抽象章节内容与分页/滚动呈现，避免把网络解析耦合到阅读 UI。最终渲染引擎与最低 iOS 版本在实现计划中结合工具链确认。

## 质量、安全与错误处理

- 单源超时、解析错误、空结果、HTTP 错误、Cookie/登录失效应区分呈现；搜索采用部分成功语义。
- 书源是用户提供的不可信输入。校验 URL/JSON 结构，限制脚本执行时间与资源；避免规则响应阻塞主线程或越权访问设备数据。
- 读者应能在无网络时打开已缓存章节；网络不可用不应破坏本地书架或阅读位置。
- 不上传查询、书源、阅读位置或缓存内容；访问第三方网站时只发送完成该来源请求所必需的信息。
- 不承诺兼容全部 Legado 扩展或每个社区书源；通过来源测试和兼容性报告，让用户知道具体失败阶段。

## 验收标准

1. 可导入合法 Legado 单源和源数组 JSON，错误 JSON 有可读错误提示；导入后的来源可启用、停用、编辑和单独测试。
2. 对多个来源搜索时，并发数受控；结果可以在全部来源结束前显示；一个来源超时/失败不影响其他来源返回结果；聚合结果保留来源出处。
3. 搜索命中的书可以进入详情、加载目录、打开章节；支持本地恢复阅读位置和用户触发的章节缓存。
4. CSS/XPath/JSONPath/正则/JavaScript 规则、请求模板、Cookie 与请求头各有 fixture 覆盖；所有支持范围均有失败样例和回归测试。
5. 单元/集成测试覆盖导入、规则解析、并发搜索、超时/取消、结果聚合、目录缓存、章节缓存和阅读位置恢复；UI 测试覆盖“导入书源→搜索→详情/目录→阅读”的主流程。
6. 代码、配置和发布设置不包含自建后端依赖、广告、iCloud 同步、标注/笔记/书签或统计功能。

## 分阶段建议

1. **搜索与兼容性基础：**新仓库骨架、书源 JSON 导入/管理、请求层、核心解析规则、并发搜索、逐源诊断。以“有效搜索命中”为首个可验证里程碑。
2. **阅读闭环：**详情/目录、阅读器、来源切换、本地阅读位置、章节缓存和书架。
3. **扩大兼容度：**根据真实来源 fixture 补足 Legado 规则边缘行为、登录/Cookie 流程和调试体验；每次增加能力都由回归用例保护。

## 参考项目中采用的经验

- 从 Legado 借鉴书源导入/管理、来源级搜索状态、多源搜索、来源切换、目录/章节缓存、书架管理与阅读外观设置。
- 从 Yuedu 借鉴模块边界、独立网络/解析管线和契约/fixture 测试思路；不采用其本地格式阅读范围。
- 不把参考项目视为可直接合并的代码模板；依赖、代码和素材须逐项审查许可证。
